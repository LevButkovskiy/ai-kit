# ai-kit

Переносимая конфигурация Claude Code: гейты на коммит, ревьюеры кода, форматирование.
Один git-репозиторий, подключаемый к любому проекту — без копирования файлов между репозиториями.

## Требования

- Claude Code
- `jq` — нужен скриптам хуков

## Установка

В любом проекте:

```
/plugin marketplace add LevButkovskiy/ai-kit
/plugin install ts-core@bulevo
```

Выбирайте scope **User** — кит будет действовать во всех ваших проектах.
Маркетплейс достаточно добавить один раз на машину.

Проверка — `/hooks`: должны появиться хуки с источником `Plugin Hooks`.

## Что вы получаете

**Автоматически**
- Форматирует каждый изменённый `.ts/.tsx/.js/.jsx` файл через prettier (пропускается, если prettier не установлен)
- Блокирует `git commit`, когда гейты проекта не проходят
- Блокирует `git commit --no-verify`
- Запрещает агенту править `.claude/gates.json`

**По запросу**
- `/ts-core:review` — запускает подходящих ревьюеров параллельно, отдаёт один сводный вердикт
- `@reviewer` — корректность
- `@security-reviewer` — авторизация, инъекции, секреты, утечки данных
- `@architecture-reviewer` — дублирование, границы модулей, неуместный код

## Включение гейтов в проекте

Гейты выключены, пока проект их не определит. Создайте `.claude/gates.json`:

```json
{
  "commands": [
    { "name": "types", "cmd": "pnpm typecheck" },
    { "name": "tests", "cmd": "pnpm test" }
  ]
}
```

- `name` — короткое и стабильное; попадает в `metrics.jsonl` и становится вашей статистикой
- `cmd` — любая команда шелла; считается пройденной при коде возврата 0
- Порядок важен: прогон останавливается на первом провале, поэтому быстрые проверки ставьте первыми

`gates.json` коммитьте. `.claude/metrics.jsonl` добавьте в `.gitignore`.

Без этого файла кит всё равно форматирует и ревьюит — просто не блокирует коммиты.

## Метрики

Каждый прогон гейта дописывает строку в `.claude/metrics.jsonl`:

```bash
# соотношение pass/fail
jq -r .result .claude/metrics.jsonl | sort | uniq -c

# какой гейт падает чаще
jq -r 'select(.result=="fail") | .gate' .claude/metrics.jsonl | sort | uniq -c
```

## Обновление кита

```
/plugin marketplace update
/reload-plugins
```

Выполняйте в любом проекте после того, как запушили изменения в этот репозиторий.

## Аудит кита

Откройте этот репозиторий в Claude Code и запустите `/self-audit`.
Он загружает актуальную документацию Claude Code и сообщает, где конфигурация
расходится с задокументированными схемами. Запускайте после обновления Claude Code.

## Решение проблем

**Хуки не срабатывают** — `/hooks` покажет, зарегистрированы ли они, `claude --debug` —
запустился ли скрипт и что вернул. Самая частая причина на Windows: `jq` не в PATH
у процесса Claude Code.

**Гейт всегда падает** — запустите команду из `gates.json` вручную в корне проекта.
Гейт, падающий по причинам, не связанным с кодом, хуже отсутствия гейта.

**Команда не найдена после обновления** — `/plugin marketplace update`, затем `/reload-plugins`.

## Структура

```
.claude-plugin/marketplace.json   каталог
plugins/ts-core/                  плагин
  .claude-plugin/plugin.json      манифест
  hooks/hooks.json                привязка хуков
  scripts/                        gate.sh, format.sh
  agents/                         ревьюеры
  commands/                       /ts-core:review
.claude/skills/self-audit/        аудит этого репозитория по актуальной документации
```
